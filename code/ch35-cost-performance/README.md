# ch35 成本与性能优化 —— 配套示例

《开源 Agent 架构技术全书》第 35 章的参考实现。一个"成本-延迟实验室"，把书里每一条变成可测量的开关：

1. **成本模型**：一次任务拆成 输入 / 输出 / 缓存读 / 缓存写 / 工具往返 五项；
2. **提示缓存模拟器**：前缀哈希匹配 + TTL，测命中率，演示"动态内容混进前缀 → 缓存基本失效"；
3. **模型路由**：按难度分级 + 级联（小模型校验失败则整任务用大模型重跑）；
4. **语义缓存**：纯标准库的字符 bigram 余弦相似度，演示近似命中与上下文指纹校验；
5. **延迟模型**：工具并行把求和变成取最大值；
6. **对照实验**：同一批任务跑"基线 / 优化 / 反例"，输出成本与延迟对比。

> 所有数字都来自本文件的模拟与本地**示意价目表**，不是任何真实厂商的报价或基准结果。

## 依赖

- Python **3.8+**，**只用标准库**，无需 `pip install`；
- 默认 mock 模式**不需要任何 API Key**。

## 安装

```bash
cd code/ch35-cost-performance
python -c "import sys; print(sys.version)"
```

Windows 下用 `py -3` 代替 `python`。

## 运行

```bash
# 1) 完整对照实验（基线 / 优化 / 反例 + 语义缓存演示）
python main.py

# 2) 真实 API 跑一次，用返回的真实 token 数按价目表算成本
export OPENAI_API_KEY=sk-xxx
export OPENAI_BASE_URL=https://api.openai.com/v1     # 可选，任意 OpenAI 兼容端点
export OPENAI_MODEL=gpt-4o-mini                       # 可选
python main.py --live
```

参数：`--live`、`--model`、`--base-url`。

## `--live` 所需环境变量

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `OPENAI_API_KEY` | 是 | — | OpenAI 兼容接口的密钥 |
| `OPENAI_BASE_URL` | 否 | `https://api.openai.com/v1` | 接口根地址，可指向任意兼容端点或本地网关 |
| `OPENAI_MODEL` | 否 | `gpt-4o-mini` | 模型名 |

`--live` 只跑一次真实调用：取回 `usage` 里的真实 token 数，按 large 口径折算成本，并和 `estimate_tokens()` 的粗估对比。**判定器与模拟部分不受影响**——真实模型不在示意价目表里，所以折算只用于看量级。

## 三组配置在演示什么

| 配置 | 开关 | 现象 |
|---|---|---|
| 基线 | 无裁剪 / 无缓存 / 全大模型 / 工具串行 | 输入 token 随步数平方增长（12 步任务输入 4.7 万 token） |
| 优化 | 裁剪 + 缓存 + 路由(级联) + 工具并行 | 同一批任务成本与延迟同时下降 |
| 反例 | 把每轮动态内容放进前缀 | 缓存命中率从 97.6% 掉到 12.2%，成本回升 |

级联那一档特意让 T-04 的小模型过不了校验：它会被大模型**整任务重跑一遍**，因此成本与延迟都接近翻倍——这是级联的尾部代价，报告里会单列"级联升级 N 次"。

语义缓存演示三个查询：首次查询走模型、近似问法命中缓存、**同一问题但上下文指纹不同则拒绝复用**（答案依赖会话或权限时，相似不等于等价）。

## 已知限制

- 价目表是**示意值**（`small` / `large` 两个虚拟档位），只演示成本算法，生产环境要换成真实价目表并定期更新；
- token 数是**模拟出来的**（按步数和裁剪策略推算），不是真实分词结果；`--live` 才能看到真实 usage；
- 延迟是按"TTFT + 输出速率 + 工具耗时"推的模型，不含网络抖动、排队与限流；
- 提示缓存用哈希近似前缀匹配，真实的按 token 逐个比对，边界条件（部分命中、缓存失效后重算）没有完全模拟；
- 没有实现流式与投机解码的模拟（前者只影响感知延迟、不影响 token 与总耗时；后者需要特定模型组合）；
- 语义缓存用字符 bigram，不是语义嵌入；真实系统应该用向量库，并额外做答案有效期与副作用校验。
