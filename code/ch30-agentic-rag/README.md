# ch30-agentic-rag —— Agentic RAG 最小可实现

第 30 章《Agentic RAG：让检索从预处理变成主动决策》的配套代码。

同一份语料、同一批问题，让「朴素 RAG」和「Agentic RAG」两条管线各跑一遍，然后在命中率、支撑率、忠实度、平均检索次数四个指标上对照。

## 目录

```
ch30-agentic-rag/
├── main.py             # 两条管线 + 评估
└── README.md           # 本文件
```

## 依赖

- Python 3.9 或更高
- **仅使用标准库**，不需要 `pip install` 任何东西
- `--live` 模式需要能访问 OpenAI 兼容的 chat/completions 接口（可选）

## 安装

没有安装步骤，下载后直接跑：

```bash
cd ch30-agentic-rag
python main.py
```

Windows 控制台若出现中文乱码：

```powershell
$env:PYTHONIOENCODING="utf-8"; python main.py
```

## 运行命令

| 命令 | 作用 |
|---|---|
| `python main.py` | 跑全部演示（朴素 / Agentic / 指标对照） |
| `python main.py --only naive` | 只看朴素 RAG 管线 |
| `python main.py --only agentic` | 只看 Agentic RAG 管线 |
| `python main.py --only metrics` | 只看指标对照 |
| `python main.py --question "..."` | 额外跑一个自定义问题 |
| `python main.py --live` | HyDE 假设与最终措辞改由真实 LLM 生成 |

## `--live` 所需环境变量

| 变量 | 必需 | 默认值 | 说明 |
|---|---|---|---|
| `OPENAI_API_KEY` | 是 | 无 | 未设置时打印告警并自动回退 mock |
| `OPENAI_BASE_URL` | 否 | `https://api.openai.com/v1` | 任意 OpenAI 兼容网关 |
| `OPENAI_MODEL` | 否 | `gpt-4o-mini` | 生成用模型 |

```powershell
$env:OPENAI_API_KEY="sk-..."
python main.py --live
```

调用失败（网络错误、返回不是合法 JSON）时会打印告警并回退 mock，不会让链路挂掉。

## 输出怎么读

- **朴素 RAG** —— 固定流水线：检索一次 → 取最相关文档 → 拼答案。输出里会看到它只回答了问题的一部分（多子问题只答一半），并且顺手加了一句没有任何证据支撑的收尾语（引用挂着，证据里没有）——这就是引用幻觉。
- **Agentic RAG** —— 分解 → 多路检索（含 HyDE 改写）→ 取证 → 校验 → 必要时改写查询再检索。每一步的子查询、检索次数、轮次、改写次数都会打印。
- **指标对照** —— 命中率、支撑率、忠实度、平均检索次数。

当前基准下的实测结果：

| 方案 | 命中率 | 支撑率 | 忠实度 | 检索次数 |
|---|---|---|---|---|
| 朴素 RAG | 0.6 | 0.5 | 0.477 | 1.0 |
| Agentic RAG | 1.0 | 1.0 | 1.0 | 3.6 |

代价那一栏就是「什么时候该退回朴素 RAG」的答案：质量指标全涨，检索次数也涨了三倍多。

## 关键实现点

| 主题 | 位置 | 说明 |
|---|---|---|
| 查询分解 | `decompose()` | 按子句识别意图维度；具体维度（运费/保修/试用）覆盖宽泛维度（退货/退款）；无维度的前置定语并入后一个子句 |
| 多路检索 | `agentic_pipeline()` | 每条子查询同时跑原查询与 HyDE 假设查询，结果合并去重 |
| HyDE | `hyde_mock()` / `live_hyde()` | mock 版按维度拼假设性答案；live 版用真实模型生成 |
| 引用校验 | `verify()` | 两条：片段必须真实存在（防引用幻觉）；片段必须包含该断言声称的意图维度（防答非所问） |
| 改写再检索 | `agentic_pipeline()` | 校验不通过时，用缺失的维度词重写查询再检索一轮，仍不通过就丢弃该断言 |
| 检索排序 | `Retriever.search()` | 按「答案句有多贴题」打分，而不是整篇文档——纯文档打分会被长度带偏 |
| 指标 | `evaluate()` | 命中率按「答案真正引用了应引用文档」计，而不是「候选集里出现过」 |

## 局限（生产化时要换掉什么）

1. 检索器用词面覆盖度代替向量模型，排序特性与真实向量库不同。
2. 意图维度是写死的规则词表，生产环境要换成模型抽取，且要能处理词表外的问法。
3. HyDE 的 mock 版是模板拼接，live 版才接近真实的假设性答案生成。
4. 没有并发：子查询目前是串行检索，生产环境应并行发起以压延迟。
5. 没有真正的引用呈现层：答案里直接拼了「（来源：d1）」，生产环境要渲染成可点击的引用卡片并能回跳原文。
6. 忠实度用词面重合度近似，没有用 NLI 模型做蕴含判断。

生产环境对应替换：向量库 + 重排模型、模型驱动的分解与改写、并行检索、以及 NLI 校验器。其余接口不变。
