# 第 4 章 · 工具层：注册、校验、错误回灌与副作用

本卷第四章把"给模型一个函数调用"变成一份真正的契约：**失败是结果，不是异常；不可逆的动作不能自动重放。**

- 正文：[`tool-layer.md`](tool-layer.md)
- 配套工程产物：`dragon-agent/` 下的四个新文件（见下）

## 本章给了什么

1. **`dragon_agent/tool_schema.py`**——从类型注解生成 JSON Schema 的可选便利层（生成器不写描述）。
2. **`dragon_agent/tool_runner.py`**——批量调用的**结果对齐与失败隔离**；错误回灌的**三种形态**判定与渲染。
3. **`examples/tool_layer_demo.py`**——实跑 `default_registry`，把六件事摊开给你看。
4. **`tests/test_tool_layer_contract.py`**——28 条契约断言。

**没有改动 `dragon_agent/tools.py`**——它已经写好了，本章只读不改、只讲它的设计。

## 核心约定

> 参数校验失败**不抛异常**，返回 `ToolResult(ok=False)`，由上层回灌给模型自己改。
> 工具内部异常**也不抛异常**，同样变成失败结果。
> `replayable=False` 的工具，幂等键用过之后**拒绝重复执行**。

## 三种错误回灌形态

| 形态 | 什么时候 | 模型该做什么 |
| --- | --- | --- |
| 字段级 `field` | 参数缺失、类型不对、枚举越界 | 改参数重试 |
| 语义级 `policy` | 未知工具、权限不足、不可重放 | 换策略，别硬试 |
| 环境级 `environment` | 文件不存在、网络不可用、服务端 5xx | 重试或换条路 |

分不清这三种，模型就会对着"文件不存在"反复改参数、对着"权限不足"反复重试——两种都在烧 token，而且都修不好。

## 怎么跑

```powershell
cd dragon-agent

# 1) 演示：实跑 default_registry，退出码 0
python examples/tool_layer_demo.py

# 2) 契约测试：28 个用例
python -m unittest tests.test_tool_layer_contract
```

不需要 API Key，不联网，不装任何第三方包，也不写用户目录。

### 实跑结果

| 场景 | 结果 | 退出码 |
| --- | --- | --- |
| `python examples/tool_layer_demo.py` | 六段演示 + 自检全部通过 | 0 |
| `python -m unittest tests.test_tool_layer_contract` | `Ran 28 tests` / `OK` | 0 |

演示里几个关键数字：

- 校验失败的调用，**工具函数一次都没执行**（`invocations` 为空）；
- `send_report` 同一个幂等键调用两次 → **实际执行 1 次**，第二次 `idempotent_hit=True`；
- `submit_order` 同一个幂等键调用两次 → **实际执行 1 次**，第二次被拒绝；
- `submit_order` 不给幂等键 → 直接拒绝；
- 4 个并行调用（2 个失败）→ 返回 4 个结果，**顺序与调用一一对应**，失败不影响其他。

## 三档副作用

| 档位 | 例子 | 能重试吗 | 要幂等键吗 | 要审批吗 |
| --- | --- | --- | --- | --- |
| 只读 | 读文件、查数据库 | 能 | 不需要 | 不需要 |
| 可逆写 | 发草稿、写临时文件 | 能 | 需要（防重复） | 视情况 |
| 不可逆写 | 下单、扣款、发邮件 | **不能** | 必须，且用过就拒绝 | 必须人工确认 |

不可逆的工具在幂等键用过之后**拒绝执行**，而不是返回上次的结果——因为"返回上次的结果"等于替调用方编一个"它成功了"的答案，而实际状态未知。

## 局限（这一章不等于可以上线）

- **参数校验只有三层，而且是平面的。** `validate()` 只查必填、顶层类型、枚举（`tools.py:117-148`，作者自己注明"只实现三类检查"）——数组元素类型、嵌套对象的内部结构、`min/max/pattern`、`$ref` 都不查；schema 里没有的属性则被直接跳过（`:136-137`），模型把参数名拼错不会收到任何反馈。
- **幂等记录是进程内的无界字典，而且不按工具隔离。** `_seen_keys` 没有 TTL、没有容量上限、不落盘（`tools.py:67`）；命中时直接返回上次的结果（`:164-165`）——不同工具共用同一个幂等键，会把**别的工具**的输出返回回去。
- **不可逆保护要两个位同时成立，且命中发生在校验之前。** "必须带幂等键"这条只在 `side_effect=True` 且 `replayable=False` 时才强制（`tools.py:168`）——只标 `replayable=False` 而没标副作用的工具，不给幂等键也会照常执行。而幂等分支在 `validate()` 之前就 return（`:157-173`）——同键不同参数，照样返回旧结果。
- **文件工具没有沙箱。** `read_text_file` 把路径 `resolve()` 之后直接读（`tools.py:205-209`），不限制在工作区内——它的工具描述写着"读取工作目录下某个文本文件"，代码没兑现这一条；路径约束要靠第 9 章的护栏层，绕过护栏直调注册表就没有约束。
- **错误分类靠中文字符串匹配，工具内部的异常会被误判。** `invoke()` 先把 `TypeError` 统一改写成"调用参数不匹配"（`tools.py:178-179`），而这串在字段级标记表里（`tool_runner.py:65`）——工具内部一句 `int(x)` 失败，模型就会当成参数写错了去反复改参数。
- **注册表没有锁。** `_seen_keys` 的"查—再写"之间没有临界区（`tools.py:157-186`），而 `invoke_many(parallel=True)` 用线程池并发调用同一个注册表（`tool_runner.py:146-148`）——同一个幂等键可能被两个线程各执行一次副作用，`invocations` 的顺序在并发下也不再确定。
