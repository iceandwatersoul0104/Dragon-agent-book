# 第 9 章 · 护栏与权限：能力最小化

本卷第九章把 Agent 的"权限"从隐含假设变成显式策略：用授权范围，而不是模型自觉，来划定事故半径。

- 正文：[`guardrails.md`](guardrails.md)
- 配套工程产物：`dragon-agent/` 下的一个文件（见下）

## 本章给了什么

1. **`dragon_agent/guardrails.py`（1257 行）**——契约第 8 节约定的 `GuardrailEngine` 实现：
   - **工具三档**（只读 / 可逆写 / 不可逆写）与各自的授权流程；
   - **二次确认**：`Decision` 的三态语义（放行 / 待确认 / 终局拒绝）、带脱敏的确认卡片、审计日志；
   - **提示注入检测与缓解**：注入特征表（10 条，其中 7 条高危、3 条中等）、不可信内容分区与两端边界标记、来源可信度、参数里的高危注入直接拦截、上下文降级；
   - **越权防护**：路径约束（含敏感路径表）、资源约束（单次 + 累计）、速率约束；
   - **输出净化**：凭据泄露按安全事件拦截，注入回显拦截，软脱敏接口。
   契约里的 `Decision` 三个字段一个没动，新增字段全部带默认值，旧写法不受影响。
2. **`examples/guardrails_demo.py`**——实跑演示：八段场景 + 接进第 6 章主循环的端到端验证。
3. **`tests/test_guardrails.py`**（544 行）——离线单元测试：45 条断言。

## 三个核心结论

### 1. 没在策略里登记的工具一律拒绝

工具注册表里挂着的工具是**这个进程能调的**；策略表里登记的工具是**这个 Agent 被授权调的**。两张表不是一回事。默认拒绝意味着"没配置"的结果是"不能用"。

```python
        policy = self._policies.get(name)
        if policy is None:
            # 能力最小化的落点：**没授权就没有能力**。
            return self._finish(
                Decision(
                    allow=False,
                    reason=f"工具 {name} 未在护栏策略中登记——未授权的工具一律拒绝",
                    code="tool_not_granted",
                ),
                name, policy, args,
            )
```

### 2. 没有确认通道时停下来等人，绝不默认放行

自动放行只能来自一个明确的"人点了同意"，不能来自"没人反对"。

```text
  待人工确认  [confirm_required]  需要人工确认，但当前没有确认通道：
【待确认动作】
  动作    : submit_order
  档位    : 不可逆写
  触发原因: 不可逆写
  参数    : {'qty': 3, 'sku': 'WIDGET-1'}
  可逆性  : 不可逆——执行后无法自动回滚
  影响范围: 单次 qty 上限 100
  建议    : 核对参数后再放行；放行记录会写进审计日志
```

### 3. 检测是辅助，授权才是防线

注入特征表是启发式的：改写、编码、拆字、翻译都能绕过，误报也会发生。真正把事故半径压住的是能力最小化——**被绕过了也损失有限**。所以检测只用来标源、触发降级、拦参数里的注入，不承担安全边界的职责。

| 场景 | 结果 | 退出码 |
| --- | --- | --- |
| `python examples/guardrails_demo.py` | 八段场景 + 主循环接线全部自检通过 | 0 |

| `python -m unittest discover -s tests` | `Ran 299 tests` / `OK (skipped=8)` | 0 |

演示里的关键输出：

- 未登记的工具被拒：`[tool_not_granted] 工具 drop_database 未在护栏策略中登记——未授权的工具一律拒绝`；
- 不可逆写在没有确认通道时**停在待确认**，而不是被放行；
- 参数里带**高危**注入特征被直接毙掉：`[injected_argument] 工具参数中检测到注入特征（…），拒绝执行`（中等特征只标不拦，见正文 4.1 节）；
- 越权三条约束各拦各的：`[path_denied]` / `[value_exceeded]` / `[rate_limited]`；
- 输出里的密钥被拦：`[secret_leak] 输出中检测到凭据（密钥/令牌），按安全事件拦截，不进入答案与状态`；
- 接进主循环后，模型想下的单**一次都没执行**（`工具实际执行次数：0`），拒绝理由回灌给了模型。

## 局限（这一章不等于可以上线）

- **注入检测是启发式的**：改写、编码、拆字、翻译都能绕过，误报也会发生。它不是安全边界。
- **护栏与被护的模型同进程**：模型读得到的内容，护栏未必读得到；护栏也看不见工具内部做了什么。
- **路径约束依赖路径解析**：符号链接、挂载点、特殊文件都可能绕开前缀比较。
- **确认环节是同步阻塞的**：高频批量场景不适用，应改成批量审批；人不在时会卡住。
- **没有跨进程/跨机的策略存储**：策略表在内存里，多 worker 需要外部化。
- **审计日志只在内存里**：本模块提供 `report()` 摘要，落盘要接第 12 章的 trace 设施。
- `residual_risks()` 把上面这些写成了程序可读的清单，会打印在启动日志里——**它不是免责声明，是使用说明**。
