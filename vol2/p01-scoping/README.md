# 第 1 章 · 立项：把想法变成一份可执行的需求

本卷第一章不写 Agent 代码，只做一件事：**在写第一行代码之前，把"我想做个 Agent"变成一份别人拿着能独立实现、而且能判断做没做到的规格。**

- 正文：[`scoping.md`](scoping.md)
- 配套工程产物：[`dragon-agent/specs/`](../../dragon-agent/specs/)

## 本章给了什么

1. **一份可填写的需求规格模板**——九个章节，把"任务定义 / 输入输出契约 / 可用工具清单 / 决策边界 / 成功判据 / 失败定义 / 明确不做的事 / 评测与观测 / 预算与约束"固化成结构。
2. **一份填好的完整范例**——自建代码审查 Agent，覆盖 5 个工具、7 条成功判据、3 行 LLM 决策 + 5 行确定性代码、5 个退出状态、7 条"不做的事"。
3. **一个规格检查器**——纯标准库，零依赖，把九项规则变成九道检查，退出码即接口契约，可直接挂 CI 当门禁。

## 怎么跑

```powershell
cd dragon-agent

# 1) 检查成品规格：应通过，退出码 0
python specs/check_spec.py specs/code-review-agent.spec.md

# 2) 检查模板结构：只看骨架，不看内容，退出码 0
python specs/check_spec.py specs/SPEC_TEMPLATE.md --mode template

# 3) 拿模板冒充成品跑：应报出 39 处占位符残留，退出码 1
python specs/check_spec.py specs/SPEC_TEMPLATE.md

# 4) 给 CI 用的机器可读输出
python specs/check_spec.py specs/code-review-agent.spec.md --json
```

不需要 API Key，不联网，不装任何第三方包。Windows / macOS / Linux 均可运行；
终端编码装不下 emoji 时会自动退回 `[OK]` / `[FAIL]` 标记。

### 实跑结果

| 运行对象 | 结果 | 退出码 |
| --- | --- | --- |
| 范例 · spec 模式 | 9 项检查全通过，0 个错误 | 0 |
| 模板 · template 模式 | 结构完整，可以开始填写 | 0 |

| 故意写坏的规格 · spec 模式（本章开发时的反例验证用例，不在仓库里） | 10 个错误，九道规则里八道亮红灯并指出行号 | 1 |

## 检查器管什么

| 规则 | 检查内容 |
| --- | --- |
| S1 | 九个必需章节齐全、无重复 |
| S2 | 没有残留占位符（TODO / 待填 / 尖括号占位符……） |
| S3 | 成功判据 ≥ 3 条，且每条都写了「验证方式：」 |
| S4 | 决策边界每行都标注 LLM 或代码，两类都必须有 |
| S5 | 工具清单副作用只取只读 / 可逆写 / 不可逆写，工具名不重复 |
| S6 | 不可逆写工具要么写进「明确不做的事」，要么在「决策边界」里由代码把持 |
| S7 | 退出状态覆盖 `AgentResult.status` 全集（5 个） |
| S8 | 「明确不做的事」非空 |
| S9 | 预算写明 `max_steps` / `token_budget` / `cost_budget` |

## 规格怎么被下游兑现

| 规格里的东西 | 落到哪个模块 | 兑现方式 |
| --- | --- | --- |
| 可用工具清单 | `dragon_agent/tools.py` | 每行对应一个 `ToolSpec`，"副作用"决定 `side_effect` / `replayable` |
| 工具描述 | `dragon_agent/tools.py` | 工具描述即提示词，写坏了模型就调不对 |
| 成功判据 | `dragon_agent/evaluation.py` | 变成 `EvalCase.expect` 与 `forbid` |
| 明确不做的事 | `dragon_agent/evaluation.py` | 变成 `forbid` 列表，越界输出判失败 |
| 失败定义 | `dragon_agent/agent.py` | 就是 `AgentResult.status` 的五个取值 |
| 决策边界里的"代码"行 | `dragon_agent/guardrails.py` | `before_tool` 收紧权限，模型绕不过去 |
| 预算与约束 | `dragon_agent/config.py` | `max_steps` / `token_budget` / `cost_budget` / `timeout_s` |

## 局限（这一章不等于可以上线）

- **只认二级标题。** `parse_sections()` 只匹配 `## `（`check_spec.py:133`），写成 `### 决策边界` 的章节会被并进上一节，检查器还会报"缺少必需章节"——章节层级必须是 h2。
- **九项规则都是子串匹配，没有语义校验。** 退出状态只查正文里出现过 `completed` 这个词（`check_spec.py:423`），预算只查出现过 `max_steps`（`:449`），工具名在"明确不做的事"里被顺口提一次就算"已受控"（`:409`）——检查器管的是"该有的字写没写"，不是"写得对不对"。
- **占位符扫描扫全文，会误伤正常内容。** 尖括号规则 `<[^<>\n]{1,40}>`（`:64`）会把代码块里的 `<200ms>`、`<html>` 一并判成占位符，`TODO` 当普通名词出现也会命中（`:245-252`）。
- **报出的行号只有 S2 能直接跳转。** S2 用文件绝对行号（`:245`），S3/S5/S6 用的是节内相对行号（`:264-293`、`:459-474`）——样例规格里 C1 在文件第 94 行，会被报成"第 2 行"。
- **有两节根本没有内容规则。** 九项检查的清单里（`:478-489`）没有"输入输出契约"和"评测与观测"，"失败定义与退出状态"也只查字符串出现、不查触发条件与调用方动作——这两项目前靠人自觉。
- **退出码即接口，但门禁还没接线。** 退出码 0/1/2 可用，可仓库里既没有 CI 配置，也没有针对 `check_spec.py` 的测试文件——检查器自身零测试覆盖。
