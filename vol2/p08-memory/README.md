# 第 8 章 · 记忆模块：把“记住”做成可控的读写

本卷第八章把"记住"从**一个功能**换成**四个动词**：写、读、检索、遗忘。配套一份准入规则（来源可信度）、一套版本仲裁、一条 TTL 降权策略，外加两条最小检索路线（向量 / 实体图谱）和一套能跑的评测。

- 正文：[`memory.md`](memory.md)
- 配套工程产物：`dragon-agent/` 下的三个文件（见下）

## 本章给了什么

1. **`dragon_agent/memory.py`**（1033 行）——严格按契约 `_plan/_dragon_contract.md` 第 7 节实现：
   - `MemoryItem`（8 个字段，与契约逐字一致）、`Memory`（Protocol）
   - `InMemoryMemory`：基线账本——准入、版本仲裁、TTL 降权、遗忘、上下文装配
   - `VectorMemory`：切块 → 确定性哈希投影嵌入 → 余弦 top-k
   - `GraphMemory`：实体抽取 → 关系边（带有效期）→ 按实体检索
   - `evaluate_memory()` / `default_memory_cases()`：不调 LLM 的记忆评测
2. **`tests/test_memory.py`**（415 行）——33 条单元断言。
3. **`examples/memory_demo.py`**（163 行）——实跑演示：准入、版本、TTL、遗忘、两条路线对照、评测报告。

## 三条硬约束

| 约束 | 怎么保证 |
| --- | --- |
| 来源可信度 `user > tool > model` | `write_decision()` 是纯函数；`model` 写语义记忆**直接拒**，程序性降级为情景记忆 |
| TTL 到期是降权不是删除 | 过期条目乘 `TTL_DECAY = 0.25`，仍在 `recall()` 结果里，只是沉底 |
| 高可信覆盖并留版本 | 同事实键上覆盖，旧版本进 `history()`，版本号 +1；低可信来源不许覆盖高可信 |

## 四类记忆

| kind | 含义 | 写入时机 | 冲突规则 |
| --- | --- | --- | --- |
| `working` | 工作记忆（草稿、工具返回值） | 随手写 | 不冲突，任务结束即弃 |
| `episodic` | 情景记忆（事件 + 结果） | 任务完成点写一次 | 只追加 |
| `semantic` | 语义记忆（事实、偏好） | 来源可信才写 | 原地更新，留旧版本 |
| `procedural` | 程序性记忆（SOP） | 连续成功 3 次才固化 | 按版本发布 |

## 怎么跑

```powershell
cd dragon-agent

# 1) 演示：离线跑通，退出码 0
python examples/memory_demo.py

# 2) 单元测试：33 个用例
python -m unittest tests.test_memory
```

**不需要 API Key，不联网，不装任何第三方包。** 本章模块没有环境变量——它完全离线，只有 `memory.py` 内部的可注入时钟（`clock`）用于确定性地测 TTL 与新鲜度。

最后一行那个"向量路线多捞了一条"，是本章要展示的核心事实：**哈希投影不是语义模型，它忠实复刻了向量检索的实体串台盲区。** 换真的 embedding 模型能缓解时间指代与否定条件，**缓解不了这一条**。

## 局限（明确：这些地方还不等于可以上线）

- **嵌入不是语义模型。** `hash_embed()` 是确定性哈希投影，只认字面。它能跑通链路、能复刻盲区，但**不能**对外宣称是语义检索。真上线要换成真 embedding 模型，并把元数据过滤、实体锚定、重排一并补上。
- **规则抽事实键必然是近似。** "Orion 项目预算是 12 万元"和"Orion 预算调整为 12 万元"会算成两个键，旧值不会被覆盖。规则仲裁**不等于**语义仲裁。要精确，得让写入方显式给键或上抽取模型。
- **规则抽实体和关系。** 只认「X 的 Y 是 Z」和「X 是 Z」两种形状；"张工"和"张三"分不开。**实体消歧没解决之前，不要在生产上开自动建边**——会稳定产出一张错图。
- **没有持久化。** 账本在内存里，进程退出就没了。要落盘得自己接文件或数据库，并保证写操作原子。
- **没有并发控制。** 单线程假设。多个线程同时 `write()` 会在"读当前版本 → 判断覆盖 → 写历史"之间产生竞态。
- **TTL 没有清理策略。** 过期条目只是降权，库里会积灰。归档或清理要上层自己做。
- **评测集只有 8 条。** 覆盖了四类记忆、三种来源、版本覆盖、TTL、拒写，但**远不够**做回归门禁。上线前至少要扩到覆盖真实失败样本的规模。
- **没有鉴权，没有多租户隔离。** 库里所有条目对所有调用方可见。
