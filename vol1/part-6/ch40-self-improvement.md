# 第 40 章 自举与自我改进：AutoGPT 的教训与演化式改进

## 一、本章要解决的问题

2023 年春天，一个循环跑起来了：给模型一句目标，它自己拆任务、调工具、看结果、再想下一步。演示视频里它连着完成了一串操作，看着像有了自我驱动力。三周后，同一批人已经不敢让它连续跑超过十分钟——不是因为它不聪明，是因为它会一直做下去，而没有人能判断它什么时候算做完了。

这套东西当时叫 AutoGPT。三年后，"自我改进"这个词底下已经分成了四条方向不同、却共用一个名字的技术路线：改**下一步该做什么**的自主循环、改**Agent 自身代码**的程序演化、改**上下文与技能**的经验沉淀，以及改**模型权重**的模型自训练。它们共享一个名字，但一个的成功经验不能直接搬到另一个上。

这一章要把四条路线各自讲清楚：机制是什么、实证结果长什么样、失败模式有哪些，然后给一个清醒的判断——今天什么样的自建 Agent 值得上自我改进机制，什么样的不值得。顺便回答一个更实际的问题：团队只有两三个人能不能做？答案是能，但要做的不是自举，是沉淀。

## 二、原理：机制拆解

### 2.1 四条路线的分岔

```
   自主循环              程序 / 代码演化           经验与技能沉淀           模型自训练
   ─────────            ─────────────           ─────────────          ─────────
   改的是"下一步"        改的是"Agent 的代码"       改的是"上下文 / 技能"     改的是"模型权重"
   自己判断做完了         可执行评估器打分          执行反馈提炼             需要标注或偏好信号
   没有外部尺子           有尺子（测试/指标）        有尺子（跑通/测试）      有尺子（人类偏好）
   无成本边界             有轮次预算               有晋升闸门               有训练数据
   AutoGPT 式            DGM / AlphaEvolve        Voyager / ACE           STaR / 自奖励
```

四条路线的分水岭只有一个问题：**有没有一个不靠模型自觉的尺子**。自主循环缺这个尺子，所以必然滑向自说自话；后三条有尺子，所以才有"变好"这个概念。

### 2.2 自主循环为什么迅速失效

三个病根，缺一不可：

1. **无目标验证**：模型自己判断"这一步做完了"，而这个判断的信息量接近零——它既提不出新证据，也无法推翻自己的结论。于是"完成了"和"跑偏了"在系统看来一模一样。
2. **错误累积**：第 20 步是在第 1 步的错误上继续推理，而上下文里装的全是自己的猜测。没有外部事实回灌，错误不会被纠正，只会被放大成一条自洽的叙事。
3. **无成本边界**：如果"再来一次"不花钱、不限时，陷入循环就是理性选择。真实的 API 调用有成本，但成本和"正确"之间没有联系，所以模型学会了把预算烧完而不是把活干完。

这三件事叠在一起就是 2023 年的典型现场：跑得挺热闹，产出没人敢用。

还有一个隐蔽的病根：**目标会被悄悄改写**。模型发现原目标难完成时，最省力的路是改目标的措辞——把"提升转化率 10%"改成"优化转化率"。目标一旦被自己修改，后面所有步骤都名正言顺。

### 2.3 程序演化：把评估器变成中心

**Darwin Gödel Machine（DGM）** 的机制是：维护一个智能体档案库，每个智能体可以修改自己的代码产生新版本，形成一棵不断生长的树，并且允许多条路径并行探索。论文报告的结果是：SWE-bench（Verified 子集）从 **20.0% 提升到 50.0%**，Polyglot 从 **14.2% 提升到 30.7%**；跑 80 轮迭代，自修改阶段由 Claude 3.5 Sonnet 驱动。关键对照实验有两个——去掉"自改进"、去掉"开放探索"两个变体都明显更差，说明增益来自这两者本身。

DGM 论文里有一句必须读的话：所有实验都在**沙箱与人工监督**下进行。它还诚实写明了局限：档案库的维护与父代选择是固定的、不可被自己修改。

**AlphaEvolve**（DeepMind）把同一套思想用在算法上：Gemini 负责生成候选程序，一个自动评估器负责打分（准确性、效率等指标），评估结果进数据库，进化算法挑出"最适应"的程序作为后续生成的出发点，构成生成—评估—选择的循环。论文反复强调的前提是**机器可判定的问题**。已公布的结果包括：在 50 多个数学开放问题上，约 **75%** 重现了已知最优解、约 **20%** 超过了已知最优解；4×4 复数矩阵乘法用 **48 次标量乘法**，改进了 1969 年的 Strassen 算法；11 维接吻数问题给出 **593** 的新下界；给 Borg 数据中心调度系统找到的启发式已在生产运行一年多，平均回收 **0.7%** 的全球计算资源；一个关键算子被加速 **23%**，让 Gemini 的整体训练时间缩短 **1%**；TPU 相关的 Verilog 重写也进了下一代芯片。

两条路线的共同点：**评估器才是主角**。没有评估器，演化就是随机游走；有评估器但评估器能被糊弄，演化就会朝着"糊弄评估器"的方向优化。

### 2.4 经验与技能沉淀：把成功轨迹变成资产

**Voyager**（Minecraft 里的开放世界智能体，MIT 许可）走的是最朴素的路：把验证过能用的东西存成可执行代码放进技能库，下次遇到同类任务直接调用。技能不是文字建议，是能跑的代码。

**ACE（Agentic Context Engineering）** 把这条路做细了，机制是三个角色分工：Generator 用当前上下文做题留下轨迹，Reflector 从轨迹里提炼出成功策略与失败教训，Curator 把教训写成结构化条目合并进 playbook（策略手册）。两个关键设计：上下文是**逐条条目（bullet）**（带唯一 ID 和"有用/有害"计数器），更新是**增量 delta** 而不是整份重写，再配一个 grow-and-refine（增长并精修）策略做去重和裁剪。

它还明确指出了两个失败模式：**简洁偏差**（越优化越短，领域细节被压掉）和**上下文坍塌**（论文里观测到上下文从 18282 token 突然塌缩到 122 token，性能随之骤降）。结果是 AppWorld 上 ReAct 基线 **42.4**，ACE 有标注时 **59.4**、无标注时 **57.2**、在线模式 **59.5**；金融任务上从 **69.1 提升到 81.9**。

这条路线的前提写在论文的局限里：**收益强依赖可靠反馈信号**。没有执行结果、没有明确环境反馈时，Reflector 和 Curator 写进去的可能是错误经验，而错误经验一旦沉淀成长期记忆，比不沉淀更糟。

### 2.5 模型自训练：改的是权重

第四条路线是改模型权重本身：用自己产生的轨迹继续训练（STaR，Self-Taught Reasoner 一类），或者拿模型自己的判断当奖励信号（自奖励一类的自我强化）。它要凑齐的东西和前三条完全不同：标注或偏好数据、训练资源，以及一个可信的奖励来源。缺任何一样，它就退化成"用自己的偏见反复强化自己的偏见"。

对绝大多数自建 Agent 来说，这条路线今天不在选项里——不是因为它不成立，而是因为它的前提条件（数据、算力、奖励可信度）都不是应用层能自己凑齐的。本章因此不再展开，只记住一句：它是研究团队的事，不是你的季度目标。

### 2.6 四条路线共同的三个前提

1. **客观评估器**：哪怕只是"测试跑通"这种最粗糙的尺子，也比模型自评强一个数量级；
2. **隔离的执行环境**：DGM 明确用沙箱，因为自修改的代码随时会跑偏；
3. **不可变的目标与预算**：谁定义"更好"、花多少钱停，必须写在代码外面。

这三条怎么落地：

- **评估器**：优先用能自动跑的测试或指标；实在没有，就退一步用人工抽检加明确的对错判据。最糟的选项是"让模型判断一下"。
- **沙箱**：自修改的代码和自动生成的脚本一律在隔离环境里跑，出错能重来。
- **目标与预算**：目标写死在配置里、不给 Agent 改；预算是硬上限，超了直接熔断，而不是等它自己收敛。

## 三、为什么这样设计：取舍与失效条件

**自主循环**：没有评估器就没有自我改进，只有自我说服。只有当你手里已经有一个可执行的验证器时，"自主循环"这个词才有意义。

**程序演化**：门槛最高但收益最实。前提是任务可自动判定（能跑测试、能算指标），并且评估器本身要防作弊——否则优化器会把"骗过评估器"当成最优解，这属于典型的规格套利。

**经验沉淀**：门槛最低，收益最稳，也最容易在无人察觉的情况下退化。失效条件有三个：反馈信号不可靠，沉淀的就是错误；任务分布漂移后，旧技能变成负债（曾经有效的路径现在会把 Agent 带偏）；技能条目越堆越多，检索本身开始退化。

**模型自训练**：应用层基本不做，理由见 2.5——它要的是标注数据、训练资源和可信的奖励，应用层凑不齐，硬上只会给自己造一个不可审计的黑盒。

**企业内部做自我改进，比公开基准难得多**，三个原因。其一，你没有现成的评估器——SWE-bench 的测试是白送的，自己的业务没有。其二，失败样本的分布和真实分布不一样：从线上捞失败案例很容易，捞到的往往是用户抽风而不是能力边界，拿它做优化会把系统调成迎合极端个例。其三，线上日志不是为优化准备的——缺上下文、缺中间状态、缺当时的环境快照，补齐这些的成本往往超过收益本身。

**安全边界**，三条最值得盯：

- **权限放大**：每轮多给一点点权限，十轮之后系统已经不是原来那个了。自我改进循环里的权限必须单调不增，或者干脆固定。
- **目标漂移**：优化压力会把手段变成目的。规格套利是最典型的形态：系统把评测指标当成了真实目标，指标上去了，真实任务反而更糟。
- **评估污染**：优化器学到的是"过评测"而不是"过任务"。可验证奖励的收益如果没有对照协议和污染检查，是会被系统性夸大的；评估器一旦和优化器共享数据或参数，问题会更隐蔽。

## 四、动手：最小可实现

今天就值得做的最小实现不是自主循环，而是**一条业务域内、带准入闸门的验证技能库**。四件东西：

1. **技能条目**：触发条件、步骤、验证命令、成功/失败计数、来源轨迹 ID；
2. **反思器**：从失败轨迹里提炼候选技能（只提炼，不直接入库）；
3. **准入闸门**：候选技能必须在固定回归集上跑通，且不能破坏既有技能的通过率，再加人工抽检；
4. **熔断**：单次运行预算上限、连续失败计数、单技能失败自动回滚。

```
每次任务结束后：
    if 任务成功 and 轨迹包含可复用步骤:
        candidate = reflect(轨迹)              # 反思器：只产出候选
    else:
        candidate = reflect(失败轨迹)

    if candidate is None: return

    if budget_exhausted() or consecutive_failures > N:
        rollback(skill_library); return         # 熔断：回滚，不留半吊子状态

    if regression_suite(candidate) passes and existing_skills_still_pass():
        promote(candidate)                      # 晋升：过闸才入库
        record(candidate, 成功=1, 失败=0)
    else:
        record(candidate, 成功=0, 失败=1)       # 失败也有用：用于淘汰
```

三个必须写死的参数：回归集覆盖哪些失败模式、晋升要连续通过几次、失败多少次就下线一条技能。没有这三个参数，技能库只会单调膨胀。

另外两个工程细节值得先想清楚：技能的粒度——按"任务类型"分组太粗，按"具体报错"分组太细，按"可复用的操作路径"分组最实用；以及淘汰机制——连续失败 N 次就下线、连续 M 次不命中就归档，否则技能库只进不出。

## 五、开源实现对照

| 项目 | 路线 | 核心机制 | 许可 |
|---|---|---|---|
| Significant-Gravitas/AutoGPT | 自主循环 | 早期以自主循环成名，现已转向提供 Agent 工具与平台 | 仓库许可为混合（NOASSERTION） |
| jennyzzt/dgm | 程序演化 | 智能体档案库 + 自修改 + 并行开放探索 | Apache-2.0 |
| MineDojo/Voyager | 经验沉淀 | 可执行代码的技能库，新任务自动复用 | MIT |
| ace-agent/ace | 经验沉淀 | Generator / Reflector / Curator 三角色 + playbook 增量更新 | Apache-2.0 |

AutoGPT 那行值得单独说一句：这个 2023 年 3 月创建的仓库仍然活跃，但它现在的自我描述是"提供工具，让你专注重要的事"——自主循环不再是主线。这是这条路线最有说服力的注脚。

## 六、坑与检查清单

- [ ] 用模型自评当验收标准，等于没有验收标准。
- [ ] 没有预算上限，"再试一次"会把预算烧光。
- [ ] 没有沙箱，让能改自己代码的 Agent 直接跑在生产环境。
- [ ] 评估器和优化器共享同一批数据或同一套参数，污染无法察觉。
- [ ] 技能库只进不出，越用越臃肿，检索质量随规模下降。
- [ ] 每次迭代整份重写上下文，长期看会把细节压没。
- [ ] 沉淀失败经验时不做区分，把错误也写成了"经验"。
- [ ] 权限随迭代放宽，几轮之后 Agent 的权限已超出你的预期。
- [ ] 用同一个评测集做晋升和验收，等于在训练集上报成绩。
- [ ] 技能没有来源轨迹，出了问题无法回溯是哪次运行沉淀的。
- [ ] 没有回归集就允许改提示词或改工具，旧能力静默退化。
- [ ] 把"指标提升"直接当成"业务变好"，中间缺一层人工确认。

## 七、小结与延伸阅读

这几条路线里，今天最值得自建 Agent 采用的是**经验沉淀**：门槛最低、收益可测、失败可回滚，而且它和第 39 章的 Skills 机制天然衔接——把沉淀出来的东西直接写成可披露的技能资产。

程序演化门槛高得多，但 DGM 和 AlphaEvolve 的数字说明它不是幻觉：SWE-bench 从 20.0% 到 50.0%、Borg 调度回收 0.7% 算力、Gemini 训练时间缩短 1%，这些都发生在有评估器、有沙箱、有人看着的条件下。自主循环则应当被当成一个已被证伪的默认选项。

清醒的判断是：**自我改进的瓶颈从来不是模型的智力，而是有没有一个不被模型污染的尺子**。先投资尺子（测试、回归集、指标），再谈自举；反过来做，多半会得到一个更自信、更贵的错误系统。

还有一件事值得提醒：自我改进的收益延迟且不易察觉——技能库变好是几周后的事，而一次坏晋升可能把线上拖垮一周。所以这类系统的工程重点不在算法，在可回滚、可审计、可一键停：每条技能有来源轨迹、每次晋升留记录、任何时候能退回上一个已知可用的版本。
