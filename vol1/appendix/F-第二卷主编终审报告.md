# 附录 F 第二卷主编终审报告

本报告记录《开源 Agent 架构技术全书》第二卷《自建 Agent 实践手册》定稿前的终审过程、改动清单与遗留问题。

第二卷和第一卷的验收方式不一样，这是必须先说清的一点。

第一卷讲的是"别人怎么做的"，它的错误大多是**事实错误**——版本号写错、许可证写错、引用了不存在的章节。这类错误靠联网核实就能查出来。第二卷讲的是"我们怎么做"，它自带一套**能跑的代码**：`dragon-agent/` 这个工程，14 个模块、13 个示例脚本、559 条断言。于是第二卷多了一类第一卷没有的错误：**正文说的和代码做的不一样**。这类错误不联网也能查——打开文件，看那一行。

而这类错误恰恰是最要命的：读者照着正文理解一套系统，照着代码搭一套系统，两者对不上，坑就转移到了读者身上。

## 一、终审怎么做的

终审分四层，每层都留下可复跑的脚本或可核对的清单，不靠印象。

**第一层：契约先行。** 在写任何一章之前，先把 `dragon-agent` 的 12 条跨模块不变式写成 `_plan/_dragon_contract.md`。这一步决定了第二卷的写法：**正文里的代码块不是示意代码，是从工程里逐字复制出来的**。所有"跑一遍看看"的程序，读者都能在 `dragon-agent/` 里找到同名文件。

**第二层：机检（脚本，可重复运行）。** 第二卷的机检脚本比第一卷多，因为要查的东西不一样：

| 脚本 | 查什么 | 为什么第一卷不需要 |
| --- | --- | --- |
| `_plan/_lint_vol2.py` | 七节结构逐字一致、篇幅、编码、行尾、README 完整性、实跑测试 | 第一卷的 `_lint.py` 已覆盖前半 |
| `_plan/_code_ref_check.py` | 正文代码块 × 仓库文件**逐字比对** | 第一卷示例与正文不是同一份东西 |
| `_plan/_xcheck_vol2.py` | 正文里的 GitHub 链接与已核实清单双向对账（仓库、许可证） | 第一卷用 `_editorial_scan.py` 做过同类事 |
| `_plan/_xscan_vol2.py` | 跨章重复、术语变体、空话套话、新术语是否已登记附录 C | 第二卷术语量比第一卷大 |
| `_plan/_ref_chapters.py` | 第二卷对第一卷的交叉引用核对（章号对不上 = 读者翻不到书） | 第一卷内部引用自洽 |
| `dragon-agent/run_all.py` | 批量实跑 13 个示例 + 全量 unittest | 第一卷的 `code/run_all.py` 同构 |

**第三层：交叉审查（两路编委互审）。** 全卷按上下半卷拆给两位编委，**自己写的不审自己**。审查判据固定四条——结构、事实、术语、语气，外加一条代码引用一致性。规则是**只修这四类问题，不得删除具体案例和实跑数字**。

**第四层：全量复验。** 每一轮改动之后立即重跑机检与实跑，确认审查本身没有把结构改坏。

### 3.3 一个值得单独讲的案例：护栏工作区随 cwd 漂移

这一条不是正文问题，是**代码缺陷**，而且是在 559 条断言全绿的情况下发现的。

`guardrails.py` 的构造过程里调用 `default_policies()` 时**没有把 `workspace` 传下去**，于是策略里的路径根退化成 `Path.cwd()`——工作区边界跟着启动目录跑。在仓库根目录启动时一切正常，路径策略拦得住 `/etc/passwd`；换个目录启动，边界就跟着挪了。

修法是一行：把 `default_policies(self.workspace)` 传进去。改完 559 条断言**仍然全绿**——因为测试全都在同一个工作目录下跑，压根没覆盖"换个目录启动"这个维度。

这个案例值得留在书里，因为它说明一件反直觉的事：**测试全绿不等于实现正确**。测试只验证它覆盖到的维度；一个从未被测到的维度，错得再离谱也不会让测试变红。所以第二卷每个模块的 README 都有一节「局限」，写的不是客套话，是这一类"这里其实没测"的地方。
